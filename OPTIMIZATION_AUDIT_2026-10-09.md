# Cutline performance and reliability audit — 2026-10-09

## Scope and conclusion

The audit followed the working path from ingest and proxy generation through decode, playback, timeline edits, effects, colour/LUT processing, scopes and export. The implementation is substantially faster and the complete fixture-backed test matrix passes, but no finite review can establish that an editor has no bugs or is "100% optimized." The table below separates validated behavior from known limits.

| Area | Availability and implementation | Optimization or fix completed | Evidence | Current assessment |
|---|---|---|---|---|
| File import and relink | File probe, stream discovery, sampled fingerprint, duplicate detection, link/copy ingest, verified copy, relink and missing-media recovery are implemented. Import runs outside the UI thread. | Simultaneous ingest jobs are serialized at the project boundary. This prevents optimistic-revision races and stops several full-file copy/verify passes from competing for the same disk. Waiting jobs remain cancellable. | Media suite 69/69; application import/proxy scenario passes with generated media. | **Ready.** Verified ingest deliberately rereads the copy to prove integrity, so it trades throughput for safety. Multi-disk ingest throughput has not been benchmarked. |
| Proxy workflow | Automatic, 1080p, 720p and 540p proxies are available; playback can switch proxies on/off; export resolves originals. | Hardware decode no longer runs duplicate software read-ahead. Failed hardware decode releases its device source so CPU read-ahead can resume. | Fixture-backed media, playback and application suites; 4K hardware playback median improved from 16.17 ms to 10.48 ms. | **Ready on the tested workload.** Production camera-codec coverage still depends on installed FFmpeg/hardware support. |
| Playback scheduling | Audio-clock transport, latest-frame presentation, bounded decode pool, read-ahead, nested sequences and dropped-frame handling are implemented. | Latest-wins presentation and asynchronous read-ahead publication remove caller starvation and lock stalls. | Playback 50/50; synthetic read-ahead contention fell from 109.13 ms to 0.0118 ms. | **Ready.** End-to-end UI p95/p99 and long-session memory telemetry remain desirable. |

Device failure falls back safely. | GPU 18/18 on AMD Radeon AI PRO R9700; 4K hardware-decode/GPU-compose median 10.48 ms in the playback audit. | **Fast for the supported subset.** Cross-vendor execution was not available on this machine. |

A 50,000-clip range query improved from 3.198 ms to 0.00212 ms. | **Ready.** Transition lookup still scans the transition list because intervals are not guaranteed ordered/non-overlapping. |

Their CPU implementations remain parallel fallbacks. | Render 151/151 and GPU 18/18, including per-effect CPU/GPU comparisons and a mixed motion/grade/blur/grade chain. | **Optimized for the nine GPU-backed families.** Mesh warp, unsharp mask, glow, drop shadow, noise reduction and chroma/luma-key cleanup still use the parallel CPU path. |

| LUT import and browsing | Standalone 1D and 3D `.cube` files, domains, Adobe input ranges, browsing, preview and application are implemented. | Fixed a filesystem canonicalization error that could collapse several valid LUT files into one browser entry. ## Measured 4K CPU-effect improvements

Release build, 3840×2160 synthetic source, the same AMD Radeon AI PRO R9700 / 32-thread machine and five measured frames after warm-up. Times are medians. The baseline already included the earlier blur/sharpen/lens parallelization; this pass targeted the remaining spatial effects.

| Effect | Before | After | Speed-up | Time reduction |
|---|---:|---:|---:|---:|
| Rolling shutter | 111.7 ms | 46.8 ms | 2.39× | 58.1% |
| Mesh warp | 156.5 ms | 47.4 ms | 3.30× | 69.7% |
| Gaussian blur | 402.0 ms | 50.6 ms | 7.94× | 87.4% |
| Directional blur | 1375.9 ms | 124.3 ms | 11.07× | 91.0% |
| Unsharp mask | 317.1 ms | 58.4 ms | 5.43× | 81.6% |
| Glow | 445.6 ms | 66.9 ms | 6.66× | 85.0% |
| Drop shadow | 425.4 ms | 67.2 ms | 6.33× | 84.2% |
| Noise reduction | 3253.7 ms | 322.2 ms | 10.10× | 90.1% |
| Wave warp | 116.9 ms | 49.0 ms | 2.39× | 58.1% |
| Bulge | 59.5 ms | 40.4 ms | 1.47× | 32.1% |
| Chroma key | 187.7 ms | 45.4 ms | 4.13× | 75.8% |
| Luma key | 139.9 ms | 45.6 ms | 3.07× | 67.4% |

Raw current measurements are in `perf/2026-10-09-effects-parallel-all.txt`; the earlier playback/GPU/cache/effect baseline and its limitations are in `perf/2026-10-08-playback-gpu-audit.txt`. The complete verification record is in `perf/2026-10-09-full-regression.txt`.

## Final GPU, presentation and cache pass

| Opportunity | Implementation completed | Measured or verified result | Remaining boundary |
|---|---|---|---|
| Direct GPU texture presentation to Qt | Qt Quick imports compositor-owned D3D11 textures on the renderer's device. Leases keep a texture alive until its scene-graph node is released; a pool recycles released textures. | 1080p three-layer render: 11.1 ms with GPU read-back versus 1.3 ms direct texture. The direct path reports 0 ms read-back and passed lifetime/reuse tests. | Windows/D3D11 path. CPU fallback covers unsupported plans, nested sequences, software Qt rendering and scope-sample frames. |
| GPU spatial kernels | Ordered compute passes cover box/Gaussian/directional blur, sharpen, vignette, lens/wide-angle correction, rolling shutter, wave warp and bulge. Per-layer hybrid execution keeps surrounding colour operations on the GPU. | All CPU/GPU image comparisons pass, including mixed operation ordering. GPU suite 18/18. | Mesh warp, unsharp mask, glow, drop shadow, noise reduction and key cleanup remain parallel CPU operations. |
| Shared immutable render-cache frames | Pixel storage uses shared ownership; cache store/hit and same-format conversion share it. Any writable access detaches first. | Copy-on-write isolation and cache tests pass. This removes the earlier 3.0–3.5 ms measured 4K ownership copy from ordinary memory-cache stores and hits. | A true mutation still requires one copy; disk serialization remains an I/O operation. |

## Remaining priority order

| Priority | Remaining work | Why it is next |
|---:|---|---|
| 1 | Add GPU kernels for mesh warp, unsharp mask, glow, drop shadow, noise reduction and key cleanup | These are now the main effects that can still force an active clip to the parallel CPU compositor and miss a 4K real-time budget. |
| 2 | Add GPU-side scope reduction or asynchronous staging | Removes the periodic full-frame CPU sample that remains when scopes are visible. |
| 3 | Extend native presentation to nested-sequence plans and non-D3D platforms | Keeps more projects on the zero-read-back monitor path and adds Metal/Vulkan coverage. |
| 4 | Add transition interval indexing | Avoids the remaining linear timeline scan on projects with very large transition counts. |
| 5 | Add sustained playback/export stress, codec corpus and NVIDIA/Intel/macOS CI | Finds device/driver/codec-specific defects that one AMD Windows workstation cannot establish. |
